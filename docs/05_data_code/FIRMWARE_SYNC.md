## 1. Values to set or confirm
| Item | Software value | What to check in firmware |
|---|---|---|
| Trigger level | `TRIGGER_G = 2.0` g (PLACEHOLDER) | The same level on |a| (magnitude of the three axes, gravity included). Every system-level result depends on it; the sweep is in the report |
| Accelerometer range | `MPU_RANGE_G = 16.0` g (PLACEHOLDER) | The configured full scale. The severity study needs at least +-64 g at 200 Hz for delta-V within 10% on 80% of crash tests; the +-16 g range clips full-speed crash pulses |
| Sampling rate | `FS_HZ = 100` Hz | The IMU output rate and the window length in samples. The ASI low-pass coefficients in `severity.h` are computed for this rate; regenerate the header if it changes |
| Window | `PRE_S = 1.0` s before and `POST_S = 1.8` s after the trigger (PLACEHOLDERS), `WIN_N = 280` samples | The ring buffer must hold `PRE_N = 100` samples before the trigger; edge-repeat padding is used in software when a recording is too short |
| Gyro | clipped to +-2000 deg/s (assumed MPU-6050 maximum), converted to rad/s for the `gyro_peak` feature | Confirm the gyro range and units; VZCrash mixes gyro resolutions |
| Axes | x forward, y left, z up | The sensor mounting; a different orientation needs a rotation before the features and the severity code |
| Packet | 97-byte alert, 26-byte ACK, little-endian, tag = HMAC-SHA256 truncated to 8 bytes over bytes 0 to 88 (`docs/01_protocol/PACKET_FORMAT.md`) | Byte-for-byte layout, counter persisted in flash, same bytes on retry, one shared key |
| Re-ACK | the base remembers the last 16 accepted alerts, sends the identical ACK for an exact repeat, at most one ACK per (node, event) per retry interval, every ACK paid from the duty-cycle budget | Implement on the base station; without it a lost ACK is never repaired |

## 4. Severity header (`severity.h`)
- Plain C99, no heap, static scratch buffers (not re-entrant). Added static RAM for the saturation-aware code: 10360 bytes (a count of the arrays, ANALYTICAL); host object code added: 1998 bytes (host estimate; an ESP32 build differs).
- Release rule: horizontal acceleration below max(0.5 g, 0.1 x pulse peak) for 50 ms, capped at 250 ms; rollover flag from the gravity-frame tilt (reported, NOT in the class rule).
- Unverified constants carried in the header: the 13 Hz ASI pre-filter, the THIV flail distances. The class limits and names are our choice.
- The saturation-aware block is generated only if `data/processed/n14_model.json` exists; its constants (pulse family, saturation level, ridge coefficients) come from the tuning tests.

## 5. Delivery settings the replay assumed (change them if the firmware differs)
- Cancel windows 10, 8, 6, 5 s for Low to Critical; window fill 1.8 s; on-device compute time assumed 0.05 s (NOT measured).
- Retry: same bytes, same counter, listening window = processing + ACK airtime + margin, then retry at once (the severity table: 2, 4, 8, 12 tries for Low to Critical).
- Duty cycle 10% (not verified against WPC/DoT), token bucket capacity 360 s.
